# GA4 Funnel & Channel Analysis

Аналитический pet-проект: разбор данных GA4 в BigQuery — воронка покупок и эффективность каналов трафика. Цель — потренировать SQL (CTE, оконные функции, подзапросы) на реальной структуре данных GA4 и получить прикладные бизнес-инсайты.

## Данные

Публичный датасет BigQuery **`bigquery-public-data.ga4_obfuscated_sample_ecommerce`** — обфусцированные (анонимизированные) события интернет-магазина Google Merchandise Store. Анализируемый период: **1 ноября 2020 — 31 января 2021** (три месяца), ~4,3 млн событий.

## Стек

- **BigQuery** — хранение и обработка данных (GA4 export schema)
- **SQL** — CTE, оконные функции (`LAG`, `PARTITION BY`), подзапросы, `JOIN`, `GROUP BY`, работа с вложенными полями (`traffic_source.medium`)
- **Power BI** — визуализация результатов (интерактивный дашборд с воронкой, разрезом по каналам и срезом-фильтром)

## Структура репозитория

| Файл | Что делает |
|---|---|
| `1. Events (1st Nov to 31st Jan).sql` | Проверочный запрос — считает общее число событий за период, подтверждает, что данные подключены и период задан верно |
| `2. Funnel users (CVR).sql` | Строит воронку: считает уникальных пользователей (`COUNT(DISTINCT user_pseudo_id)`) на каждом из 5 шагов покупки, шаги упорядочены по бизнес-логике через `CASE`, а не по алфавиту |
| `3. Conversion.sql` | Тот же расчёт + конверсия между соседними шагами в % — через оконную функцию `LAG`, чтобы сравнить каждый шаг с предыдущим без дополнительных JOIN |
| `4. CVR channel.sql` | Разрез пользователей по каналу привлечения (`traffic_source.medium`): сколько посмотрели товар, сколько дошли до оплаты, и конверсия по каждому каналу |

## Результаты

### Воронка (`2. Funnel users (CVR).sql`, `3. Conversion.sql`)

| Шаг | Пользователи | Конверсия от предыдущего шага |
|---|---|---|
| view_item | 61 252 | — |
| add_to_cart | 12 545 | 20.5% |
| begin_checkout | 9 715 | 77.4% |
| add_shipping_info | 9 714 | 100.0% |
| add_payment_info | 5 751 | 59.2% |

**Инсайт:** самый широкий отвал — на входе в воронку (просмотр → корзина, 20.5%), но это нормально для e-commerce: люди сравнивают товары. Более тревожный отвал — на последнем шаге, доставка → оплата (59.2%): здесь теряются пользователи с высоким намерением купить, уже прошедшие весь путь. Именно на этом шаге теряются самые «дорогие» для бизнеса пользователи.

### Каналы (`4. CVR channel.sql`)

| Канал | Viewers | Payers | Конверсия |
|---|---|---|---|
| organic | 21 652 | 1 631 | 7.5% |
| **referral** | 17 580 | 2 903 | **16.5%** |
| (none) | 10 783 | 529 | 4.9% |
| \<Other\> | 8 184 | 449 | 5.5% |
| cpc | 2 504 | 136 | 5.4% |
| (data deleted) | 549 | 60 | 10.9% |

**Инсайт:** organic приводит больше всего трафика, но referral — при меньшем объёме — конвертирует более чем в два раза лучше (16.5% против 7.5%) и приносит больше реальных покупателей в абсолютных числах (2 903 против 1 631). Объём и качество трафика — разные метрики: самый крупный канал не всегда самый эффективный. Вывод для бизнеса — усиливать реферальные источники, а не только масштабировать поисковый объём.

## Визуализация

Результаты выгружены в CSV и визуализированы в Power BI: интерактивный дашборд с воронкой по шагам, комбинированным графиком по каналам (объём + конверсия) и срезом-фильтром по каналу.

## Как запустить

1. Открыть BigQuery console (или через `bq` CLI), доступен бесплатный Sandbox без биллинга.
2. Выполнить запросы из репозитория по порядку (1 → 4) на публичном датасете `bigquery-public-data.ga4_obfuscated_sample_ecommerce`.
3. Результаты можно выгрузить в CSV и визуализировать в любом BI-инструменте.
